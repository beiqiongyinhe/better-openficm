# OpenFicM 0.7.1

[简体中文](v0.7.1.md)

> Translation note: this is an English translation of an upstream OpenFicM release note. This repository (better-openficm) is a community-modified build of OpenFicM; release notes up to and including v0.8.0 describe upstream builds. Anything marked `[upstream legacy]` refers to the upstream project and not to the APK published by this fork -- see README.md for the certificate and checksum this fork actually ships.

0.7.1 is about turning "writing style" from an abstract setting into a complete, usable creative loop that is really wired into the Agent.

## Release highlights

### A separate reference book library

- Import TXT, Markdown and EPUB.
- Common text encodings such as UTF-8, UTF-16 and GB18030/GBK are supported.
- The original file and the normalised text live in the app's private directory and can be renamed or deleted.
- Single files, text extracted from EPUB and the character count of the body all have boundary checks.

### Lorn style distillation

- Uses the style analysis method from Lorn.NovelWriteSkills.
- Draws 6 representative samples from different places in the whole book; the whole reference book is never uploaded.
- Produces executable constraints for sentence length, rhythm, sensory detail, rhetoric, taboos and de-AI-ification.
- Each reference book can keep several reference style versions, and they can be used across works.

### Author style evolution

- When the Agent writes body text it saves the AI draft and the style that was used.
- After the author edits a chapter, the AI draft and the final text can be compared to produce a work-specific author style.
- Author styles are isolated per work and keep several versions, so they can be iterated over time.
- Reverting to the AI draft, or having no valid edits, does not wrongly trigger evolution.

### Style really wired into the Agent

- Both the assistant page and the writing page let you pick the creative style directly.
- The style is injected into the main agent and into the body-text sub-agents; it is not a UI decoration.
- The first time body text is written, and no style has been chosen yet, the Agent asks a structured question.
- `write_chapter` and `edit_chapter` record the AI draft and where the style came from.

### Mobile experience and reliability

- The style library uses mobile lists, a bottom action sheet and large touch targets.
- The narrow-screen action area of the writing page wraps automatically.
- The separate test APK now uses a consistent Release native dependency chain, avoiding a mix of CMake Debug and Release.
- Fuller usage instructions, style operation notes, privacy boundaries and troubleshooting were added.

## Why it is worth using

- No PC backend needed: manage works and run the Agent straight on the phone after installing.
- Local-first data: works, conversations, reference books, styles and indexes are stored on the phone by default.
- The Agent really collaborates: it can call tools, update chapters and settings, delegate to sub-agents and show an execution trace.
- Creative context isolation: different works have their own sessions, author style, characters, world book and index.
- A closed style loop: reference book distillation, creative selection, AI draft, author edits and style evolution form one flow.
- Provider freedom: OpenAI-compatible, Google Gemini and Anthropic are supported, with model lists or manual entry.
- Local semantic retrieval: embedding and reranking models run on the phone, with no external vector database.

## Installation notes

- System requirement: Android 9.0 or later.
- Architecture: arm64-v8a only.
- Can be installed as an in-place upgrade over the 0.7.0 stable release; the signing certificate is unchanged.
- The APK does not bundle GGUF, Agents or Skills; runtime resources are downloaded and verified on first launch.
- AI requests and style distillation use a model API that the user configures themselves.

For detailed steps see the [OpenFicM Android user guide](https://github.com/tioners/OpenFicM/blob/v0.7.1/docs/USER_GUIDE.md).

## Privacy note

Style distillation does not upload the whole reference book, but it does send up to roughly 24,000 characters of distributed samples to the model provider the user chose. Only import content you have the legal right to use, and decide whether to use it based on the provider's privacy policy.
