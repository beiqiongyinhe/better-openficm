# OpenFicM 0.8.0-better.2

本版修掉一个会让 App 直接退出的 bug，并补上此前没覆盖的侧滑返回。

## 修复：设置分类子页按返回键直接退出 App

现象：在设置里点进任一分类页（通用、连接、模型与供应商……），按系统返回键不是退回设置列表，而是**整个 App 被关掉**。同样的现象也出现在「作者文风 → 文风书库」这类真实路由页上。

根因是两条返回通道同时断了：

- React Native 只有在 `targetSdkVersion >= 36` 时才会把回调注册到 `OnBackPressedDispatcher`（`AndroidVersion.isAtLeastTargetSdk36()` 里同时判断系统版本与应用 targetSdk）。本包 targetSdk 是 36，而运行设备是 Android 14（API 34），运行时判断为假 —— **RN 从未注册回调**。
- 同时 `AndroidManifest.xml` 里的 `android:enableOnBackInvokedCallback="true"` 让系统改走 predictive back（`OnBackInvokedDispatcher`），系统返回**不再回调 `onBackPressed()`**。

于是没有任何一层接住返回事件，系统按默认行为结束 Activity —— 表现就是直接退出。设置分类页与真实路由页都依赖 JS 侧处理返回，因此一并中招。

修法是把 `enableOnBackInvokedCallback` 关掉，恢复到经典 `onBackPressed()` 链路：`ReactActivity.onBackPressed` → `ReactActivityDelegate` → `ReactDelegate` → bridgeless `ReactHostImpl.onBackPressed` → JS `hardwareBackPress`。

两处一起改，避免重新打包时被注回 `true`：

- `mobile-rn/android/app/src/main/AndroidManifest.xml`
- `mobile-rn/app.json` —— `expo.android.predictiveBackGestureEnabled`，Expo 就是用它注入上面那个 flag

## 真机实测

设备 Android 14（API 34），手势导航。

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 设置分类子页 + 硬件返回键 | 直接退出 App | 回到设置列表 |
| 设置分类子页 + 左边缘侧滑 | 直接退出 App | 回到设置列表 |
| 真实路由页（作者文风 → 文风书库）+ 返回键 | 直接退出 App | 回到设置列表 |
| 设置列表根页 + 返回键（回归） | 切回书架 | 仍切回书架 |
| 书架首屏 + 返回键（回归） | 退出 App | 仍正常退出 App |

后两项是防「返回键被吃掉」的回归验证 —— 修完之后根页返回没有被过度拦截。

## 兼容性

- 沿用 0.7.0 起的正式签名证书，可直接覆盖升级（**升级请覆盖安装，不要卸载**）。
- applicationId `com.openfic.mobile`，versionCode 15，minSdk 28，仅 arm64-v8a。签名方案仍为 APK Signature Scheme v3。
- 只改了清单里的一个开关，未新增数据表、未改模型请求逻辑，已有作品与设置不受影响。
- 关掉 predictive back 后，系统不再提供「回到桌面时把 App 缩回图标」的预览动画，返回行为与 Android 13 之前一致。
