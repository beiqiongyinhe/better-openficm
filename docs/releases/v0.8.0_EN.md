# OpenFicM 0.8.0

[简体中文](v0.8.0.md)

> Translation note: this is an English translation of an upstream OpenFicM release note; see v0.7.1_EN.md for how this repository relates to upstream.

## New: three-level notes

Mobile already had chapters, characters and a world book, but no place to keep an outline. Storing "plot direction for the three volumes", "list of foreshadowing", "character arc plan" had to be squeezed into the world book -- and the world book is scanned by consistency checks, while the system prompt requires the Agent to treat its contents as confirmed canon. **Storing unwritten plot there makes the Agent treat it as established fact**; that is semantic pollution, not a workaround.

This version adds notes, assigned to three levels following the structure a work already has:

| Level | Typical content |
| --- | --- |
| Whole book | Book-wide outline, main premise, overall character arc plan, taboo list |
| Volume | Plot direction of this volume, foreshadowing to plant or pay off in this volume |
| Chapter | What this chapter must achieve, what hook to leave, temporary memos |

The three levels reuse the volume/chapter structure the work already has and do not introduce a second hierarchy the user has to maintain. Upstream's desktop client uses free-form path categories (`/settings/characters`), which is a poor experience for multi-level path navigation on a phone and is disconnected from the work's structure.

### UI

- The top of the bookshelf gains a "Notes" entry, side by side with Characters and World book.
- The notes page groups by whole book, each volume and each chapter; each group header has a button to create a note at that level directly.
- Each note can be edited, deleted, or moved to another level with the move button -- promoting a memo that only concerns one chapter to apply to a whole volume is a common operation.

### When deleting a chapter or volume

The app first counts how many notes fall in that range and shows a dialog letting you choose "keep notes" or "delete them too". If you keep them, the notes float up automatically: deleting a chapter moves them to the volume they belonged to, and deleting a volume moves them to the whole-book level. The database foreign key uses `ON DELETE SET NULL` rather than `CASCADE`, so notes are not silently lost.

When there are no notes, the original two-button confirmation dialog is kept, adding no extra steps.

### Agent tools

Six new tools were added, whose permissions can be adjusted individually in "Settings → Tool permissions":

| Tool | Permission class |
| --- | --- |
| `list_notes` | read-only |
| `read_note` | read-only |
| `write_note` | write |
| `edit_note` | write |
| `move_note` | write |
| `delete_note` | write |

The system prompt **lists only note titles and IDs, not the body text**; when the Agent needs the content it calls `read_note` -- the same approach as skills (the prompt lists skill names and full instructions are loaded only when used). Injecting all bodies would make every request heavier, conflicting with the direction of reducing request size since 0.7.4. When there are more than 40 titles, the Agent is told to call `list_notes` for the full list.

The prompt also tells the Agent explicitly that outlines, plot direction and foreshadowing plans belong in notes and must not be written into the world book.

## Compatibility

- Uses the same release signing certificate as 0.7.0 onwards and can be installed as a direct upgrade.
- applicationId `com.openfic.mobile`, versionCode 15, minSdk 28, arm64-v8a only.
- A new `notes` table was added with a `CREATE TABLE IF NOT EXISTS` statement, created automatically on upgrade and not affecting existing data.
- The desktop client's note category tree (4 tools such as `create_note_category`) was not ported. Mobile notes belong to volumes and chapters and need no separate categories; finer organisation can use title prefixes.
