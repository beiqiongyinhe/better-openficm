## Fix: scrolling inside bottom sheets works only intermittently

Real-world testing found that dragging down in the style guide preview "did nothing", yet a quick upward flick sometimes scrolled. The `flexShrink` added to the ScrollView in 0.7.6 fixed the clipped content but not the scrolling itself being stolen.

The root cause was a snippet shared by every bottom sheet:

~~~jsx
<Pressable style={styles.modalBackdrop} onPress={close}>
  <View style={styles.sheet} onStartShouldSetResponder={() => true}>
~~~

The outer `Pressable` handles "tap the blank area to close", and the inner `onStartShouldSetResponder` was there to stop taps on the sheet content from closing it by mistake. The problem is that the latter grabs the JS responder the **instant the touch begins**, while the inner ScrollView only contends for scrolling once the finger moves. On a fast swipe the native scroll intercepts first and scrolling works; on a slightly slower touch the JS responder is set first and scrolling is blocked -- which is exactly why the same page worked only sometimes.

The fix makes the backdrop and the content siblings, with the backdrop filling the screen and placed before the content: the content naturally sits on top of the backdrop, taps on the content never hit the backdrop, and only taps outside the content close the sheet. `onStartShouldSetResponder` is no longer needed and the responder conflict disappears.

This pattern existed as 10 identical copies across 4 pages, all now consolidated into the `SheetBackdrop` component in `components/ui.tsx`, so scrolling and gestures are fixed for the following sheets:

- Style library: reference-book detail, style guide preview
- Assistant: conversation list, model selection, style selection
- Writing page: style selection, volume/chapter table of contents, export options, volume/chapter actions
- Settings: model list

The sheets in the character library, world book and bookshelf use a different `KeyboardAvoidingView` pattern and are not affected, so they were left unchanged.

## Compatibility

- Uses the same release signing certificate as 0.7.0 onwards and can be installed as a direct upgrade.
- applicationId `com.openfic.mobile`, versionCode 14, minSdk 28, arm64-v8a only.
- A pure UI gesture fix; it does not touch data, model requests or distillation logic.
