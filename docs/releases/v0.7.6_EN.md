# OpenFicM 0.7.6

[简体中文](v0.7.6.md)

> Translation note: this is an English translation of an upstream OpenFicM release note; see v0.7.1_EN.md for how this repository relates to upstream.

This version focuses on fixing three problems found in real-world testing and adds three usability improvements.

## Fix: style distillation gets stuck at "summarising the style guide"

The symptom was a fixed error after reaching the summarisation step -- "the style guide returned by the model must not be empty" -- reproducible on two devices.

The real cause was not that the model returned nothing, but that **the output was truncated and the code treated truncation as empty**. The OpenAI-compatible branch previously did not check `finish_reason` at all, so when the model hit `max_tokens` and returned `content: null` it was silently downgraded to an empty string. Reasoning tokens of thinking models also count against that ceiling, and the default ceiling was only 4,096 -- batch analysis has short output and passes, but summarisation must emit a complete guide and would exhaust the budget before the body text appeared.

- All three provider branches now check for truncation (OpenAI's `finish_reason=length`, Gemini's `finishReason=MAX_TOKENS`, Anthropic's `stop_reason=max_tokens`) and tell you directly where to raise the ceiling, instead of reporting "content is empty".
- The two distillation steps now have their own output budget floors: 8,192 for batch analysis and 16,384 for summarisation. These floors never go below the limit you configured yourself; they only guarantee that steps which structurally need long output are not starved by the default value.
- When a provider returns non-JSON, a non-object JSON value or an empty response body, the error now includes the first 300 characters of the actual response. Previously these cases only reported "unparseable non-JSON response", throwing away the only diagnostic clue.

## Fix: retrying after switching models still hits the old model

After selecting a model that had become invalid in the assistant, even switching back to a working model and tapping "Retry" or asking again produced the same error; only starting a new conversation worked.

The cause was that retries preferred the model recorded on the failed message, ignoring the user's current selection. It is now the other way round: the currently selected model wins, and the model recorded on the message is only a fallback when no model is currently available.

## Fix: style guide preview could not be scrolled through

The ScrollView in the style detail panel lacked a shrink constraint: the parent only had `maxHeight`, so content beyond it was clipped and would not scroll. The reference-book detail panel used the same pattern and was fixed as well.

## Improvements

- The reference-book detail page now shows the model actually used for distillation. Distillation always follows the default model in "Settings → Models & Providers", and previously there was no way to tell from the UI which one that was.
- A "find model" filter box was added after fetching the model list; it does substring matching on the name or model ID. Relay stations routinely return hundreds of models, and hunting through them was slow.
- "Settings → Advanced" gained an app version check that queries this project's latest GitHub Release and offers a download link. Version numbers are compared segment by segment numerically, so `0.10.0` is not judged as smaller than `0.7.5`.

## Compatibility

- Uses the same release signing certificate as 0.7.0 onwards and can be installed as a direct upgrade.
- applicationId `com.openfic.mobile`, versionCode 13, minSdk 28, arm64-v8a only.
- No new runtime dependencies; the version number is read from `app.json`, the same source as the build configuration.
