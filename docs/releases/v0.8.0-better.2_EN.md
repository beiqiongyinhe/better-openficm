# OpenFicM 0.8.0-better.2

[简体中文](v0.8.0-better.2.md)

> Translation note: unlike the other release notes in this folder, this one is **not** a translation of an upstream OpenFicM release; it describes a build produced by this fork (better-openficm) itself. For how this repository relates to upstream, see v0.7.1_EN.md and README.md.

This version fixes a bug that made the app exit outright and covers the edge-swipe back gesture that was previously left out.

## Fix: pressing back on a settings category sub-page exits the app entirely

Symptom: entering any category page in settings (General, Connection, Models & Providers, ...) and pressing the system back button did not return to the settings list but **closed the whole app**. The same symptom appeared on real routed pages such as "Author style → Style library".

The root cause was two back channels breaking at the same time:

- React Native only registers its callback with `OnBackPressedDispatcher` when `targetSdkVersion >= 36` (`AndroidVersion.isAtLeastTargetSdk36()` checks both the OS version and the app's targetSdk). This package targets SDK 36 while the test device runs Android 14 (API 34), so the runtime check is false -- **RN never registered the callback**.
- At the same time `android:enableOnBackInvokedCallback="true"` in `AndroidManifest.xml` makes the system use predictive back (`OnBackInvokedDispatcher`), so system back **no longer calls `onBackPressed()`**.

No layer therefore caught the back event and the system finished the Activity with default behaviour -- which is exactly an immediate exit. Settings category pages and real routed pages both rely on the JS side handling back, so both were hit.

The fix is to turn `enableOnBackInvokedCallback` off, restoring the classic `onBackPressed()` chain: `ReactActivity.onBackPressed` → `ReactActivityDelegate` → `ReactDelegate` → bridgeless `ReactHostImpl.onBackPressed` → JS `hardwareBackPress`.

Both places must be changed together, so that the flag is not written back to `true` on a rebuild:

- `mobile-rn/android/app/src/main/AndroidManifest.xml`
- `mobile-rn/app.json` -- `expo.android.predictiveBackGestureEnabled`, which is what Expo uses to inject that flag

## Real-device testing

Device running Android 14 (API 34), gesture navigation.

| Scenario | Before the fix | After the fix |
| --- | --- | --- |
| Settings category sub-page + hardware back key | App exits outright | Returns to the settings list |
| Settings category sub-page + left-edge swipe | App exits outright | Returns to the settings list |
| Real routed page (Author style → Style library) + back key | App exits outright | Returns to the settings list |
| Settings list root page + back key (regression) | Switches back to the bookshelf | Still switches back to the bookshelf |
| Bookshelf first screen + back key (regression) | Exits the app | Still exits the app normally |

The last two rows guard against the back key being swallowed -- after the fix the back action on root pages is not over-intercepted.

## Compatibility

- Uses the same release signing certificate as 0.7.0 onwards and can be installed as a direct upgrade (**to upgrade, install over the top; do not uninstall**).
- applicationId `com.openfic.mobile`, versionCode 15, minSdk 28, arm64-v8a only. The signing scheme is still APK Signature Scheme v3.
- Only one switch in the manifest was changed; no new data tables and no changes to model request logic, so existing works and settings are unaffected.
- With predictive back turned off the system no longer provides the preview animation that shrinks the app back into its icon when you return to the home screen; back behaviour matches Android 13 and earlier.
